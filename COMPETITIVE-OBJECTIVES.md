# GoreeCloud Music — Competitive Objectives

These objectives define the capabilities and product qualities GoreeCloud Music should compete on. They are not claims that the current repository already delivers them.

## Objectives

1. **Self-hosted usefulness without provider lock-in.** Core library browsing and playback should remain useful when optional external providers are disabled or unavailable.
2. **Source transparency beyond conventional music clients.** Source identity and availability should be independently visible and preserved through queues, playlists, history, downloads and handoff.
3. **Privacy-first personalization.** Recommendations, history, analytics and recap features should be locally processed or GoreeCloud-controlled by default, with external personalization optional.
4. **Exact recording integrity.** Routing and matching should distinguish exact, equivalent, alternate and unknown matches so users are not silently moved to a different recording.
5. **First-class multi-user architecture.** Profiles, libraries, permissions, recommendations, downloads, devices and private history should be isolated by design rather than added later.
6. **High-quality playback.** Lossless/original playback, transparent transcoding decisions, gapless albums, normalization and diagnostics should be first-class capabilities.
7. **Strong offline behavior.** Downloads, caching, integrity, revocation, storage management and degraded operation should be explicit and testable.
8. **Interoperability without architectural dependence.** OpenSubsonic compatibility and migration tools should coexist with a native GoreeCloud API and domain model.
9. **Unified GoreeCloud experience.** Web, Linux, Android and later supported clients should share GoreeCloud Music semantics and current-Stable Glaze UI while respecting platform-native behavior.
10. **Durable platform integration.** Wardveil Security, Privacy Shield, Everkeep, Identity, Mesh and Manager integration should be evidence-backed and fail closed where authorization or acceptance is absent.

## Non-objectives

- Rebranding or permanently wrapping another complete music server or client.
- Hiding provider identity behind a misleading universal availability state.
- Treating provider playback rights as permission to download, copy, cache or redistribute media.
- Sending private-library searches or listening history to external providers by default.
- Declaring Stable from documentation, build success, prototypes or incomplete platform integration.
